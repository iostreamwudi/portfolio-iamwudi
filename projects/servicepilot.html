问题与目标

客服机器人并不只是“回答问题”，还要理解连续对话、调用业务能力，并判断何时交给人工。

多轮理解

历史信息简单拼接，容易出现上下文丢失与意图漂移。

业务动作

知识回答与订单操作割裂，复合意图下难以形成完整服务。

人工接管

需要在高风险或信息不足时稳定转接，并完整传递上下文。

03

关键产品决策

01 / CONTEXT

结构化管理会话状态

把用户身份、订单、当前意图和已确认信息组织为可持续更新的状态，而不是只拼接历史消息。

02 / ACTION

让回答与业务动作协同

将知识问答、订单 Tool Calling 与人工接管放入同一处理链路，减少能力之间的割裂。

03 / RETRIEVAL

让检索理解适用边界

引入父子知识选择与受约束 Hybrid Retrieval，改善相似知识竞争和来源选择问题。

06

项目复盘

真正困难的不是把模型接进产品，而是定义它在什么情况下可以回答、可以行动，以及必须交还给人。

这次实践让我形成了一套更完整的方法：先用业务风险划定边界，再设计 Agent 的信息、动作和交接机制，最后通过稳定评测集定位问题并验证改进。
